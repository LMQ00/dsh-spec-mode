# Spec Mode 实现逻辑

这份文档写每个模块管什么、状态从哪里来、守卫按什么判、提醒什么时候挂出。

- 插件不自己存状态：状态全部从会话日志折叠得出。
- 工作树的写权限由守卫按会话拦截，只放行草稿文件。
- 访谈收尾由模型调用一次退出确认工具，用户批准后才落盘。

## 模块划分

| 文件 | 管什么 |
| --- | --- |
| index.js | 装配入口：注册投影、提示词段落、`/spec` 命令、退出确认工具、只读守卫、产出文件检查、跨会话草稿提醒 |
| state.js | 状态字段与折叠、草稿路径解析、草稿目录创建 |
| guard.js | 工具名谓词（写原语、删除类）、路径分类、入参路径收集 |
| advisories.js | 产出文件的六项检查文案：行数预算、文档规则块、进度类内容、水分小节、代码的复现步骤、决策只记结论 |
| prompt.js | 注入文本：访谈协议段落、跨会话草稿提醒 |

- 依赖方向单向：index.js 依赖其余四个，其余四个互不依赖。
- 被依赖的四个模块都是纯函数或纯数据，`node selftest.mjs` 直接测它们，不需要宿主。

## 状态模型

一个会话三样状态：

| 状态 | 含义 |
| --- | --- |
| 已提交的启用状态 | 布尔；这个会话算不算在模式里 |
| 正在执行的那次选择 | 当前这条进入命令要把它切成什么；没有正在执行的命令就是空 |
| 正在评审的退出调用 | 退出确认工具这次调用的标识；没有在评审就是空 |

- 注册为会话投影单元，只有宿主半边：不声明客户端可见的视图，不参与客户端拿到的投影快照，但会被投影缓存正常存档与恢复。
- 状态是纯 JSON；折叠函数对无关事件必须返回同一个状态引用，投影按引用相等判断有没有下游工作。
- 注册键 `spec`，状态版本 1；改状态字段或折叠语义时版本号加一，否则持久化缓存里的旧行会被前向折叠成垃圾。

### 折叠规则

| 会话日志里出现 | 折叠结果 |
| --- | --- |
| 进入命令开始（`command/run`，名字是 `spec`） | 记下这次选择：参数去空格后等于 `off` 是想关，否则想开 |
| 进入命令结束（`command/done`，标识对得上） | 成功就提交为新状态，失败就丢弃；两种都清掉这次选择 |
| 进入命令结束，标识对不上，或没有正在执行的选择 | 状态不动 |
| 退出确认工具被调用（`tool/call`，名字是 `spec_resolve`） | 记下这次调用标识 |
| 这次调用的结果回来（`tool/result`） | 结果带错误标记：清掉标识、状态不变；否则整体退出模式——启用状态置假、选择与标识都清空 |
| 其它任何事件 | 返回同一个状态引用 |

插件不写自己的事件类型：会话日志的读路径只认宿主那份已知类型清单，而日志的追加入口设不了「可忽略」标记——自建类型写出的日志之后打不开。状态因此只由上面这几种已有事件推导。

### 有效状态与已提交状态

两个读法，不能混用：

| 读法 | 含义 | 谁用 |
| --- | --- | --- |
| 有效状态 | 「正在执行的那次选择」优先，没有则用已提交状态 | 守卫、提示词段落、退出确认工具——问「这一刻算不算在模式里」 |
| 已提交状态 | 只看已提交那一项 | 进入命令的处理函数——问「这条命令进来之前是什么状态」 |

命令记录在处理器之前入日志：先追加开始、再调处理函数、最后追加结束。所以处理函数执行期间，「正在执行的那次选择」已经是本次的选择，「已提交状态」还是旧值。用错读法的后果：

| 用错的地方 | 后果 |
| --- | --- |
| 退出命令用有效状态判「本来是否开启」 | 错报未启用 |
| 进入命令用有效状态判「是否已在模式里」 | 跳过计划模式的互斥检查 |

自测脚本里有一条断言专门锁这个不变量。

### 进程内退出旁路

- 按会话记的进程内集合：退出确认工具批准后加进去，再次进入模式时移除。
- 作用范围只有一件事：批准退出的结果入日志后，**同一轮**紧接着的产出文件写入不被「还没折叠到」的投影拦下。
- 持久真相仍是那条结果的折叠；旁路只影响本进程的即时判定，进程重启后由日志恢复。
- 已批准的会话再调退出确认工具会因有效状态为假而抛错——旁路把它算作已退出。

## 生命周期绑定

| 时机 | 做什么 | 什么条件下 |
| --- | --- | --- |
| 会话创建 | 草稿提醒：草稿可能是未完成的访谈，也可能是已落盘但没删掉的残留，提醒里两种读法都写出来，让模型对照 `AGENTS.md` 与 `docs/` 自己判 | 仅根会话、当前未启用、草稿非空 |
| 工具写入落盘后 | 产出文件检查（见「检查项与触发条件」） | 见该节的触发条件列 |

- 投影不自己订阅会话事件：注册之后由框架驱动折叠，没有需要清理的订阅。
- 其余注册（工具、守卫、提示词段落、事件、可选服务注入）都挂在插件自己的生命周期上，卸载即回收。
- 子代理的判定看会话头：来源是子代理、或嵌套深度大于零的都不是访谈者，不发提醒。子代理的模式状态天然为假（它的日志里没有进入记录），守卫也不拦它。

## 工具守卫

- 同步、单调：返回文案即拒绝，返回空即放行；它排在所有「写入前」监听器之后，没有后续监听器能把拒绝翻回允许。
- 注册在全局上下文上，按调用所属的会话取状态。

判定顺序：

| 顺序 | 条件 | 结果 |
| --- | --- | --- |
| 1 | 调用没有关联会话 | 放行 |
| 2 | 该会话的有效状态为假 | 放行 |
| 3 | 工具名以 delete、remove、move、rename 开头 | 只看草稿：命中草稿就拒绝（草稿在合并进规范文件前不可删改），否则放行 |
| 4 | 工具名不是 `write`、`edit` | 放行 |
| 5 | 其余情况 | 入参里任何一个路径被判成工作树就拒绝 |

### 路径判定

| 判定的输入 | 结论 |
| --- | --- |
| 路径为空，或匹配「协议名后跟两斜杠」的形式 | 协议路径——设备地址，一律放行 |
| 按会话工作目录解析相对路径时抛错 | 工作树——失败即关 |
| 解析结果等于草稿的绝对路径 | 草稿 |
| 其余 | 工作树 |

- 草稿只匹配草稿文件本身，不匹配它的父目录。目录级放行等于把真实文档目录开了写权限；父目录由插件自己直接创建，不经过工具层。
- 入参里的路径按工具用过的几种键名收集（主路径、驼峰别名、复数形式），不认得的键就当没有路径。
- 相对路径按会话工作目录解析；宿主写文件时可能改用沙箱的工作区根作基准，两者不同时相对路径会指向另一个文件——访谈协议因此要求草稿一律写绝对路径。这是已知边界。

## 草稿路径解析

- 草稿路径 = 从会话工作目录往上找到的最近一个带 `.git` 的目录下的 `docs/spec-draft.md`；一路找不到这样的目录就用工作目录本身。
- 这套找法跟宿主的指令文件读取机制一致（默认的项目标记只看版本库目录，找不到就用会话工作目录），草稿与基线文件因此落在同一个项目里。
- 项目锚点不认项目本地配置目录，也不认用户全局配置根。
- 会话头里没有可用工作目录时，用宿主进程的当前目录。
- 草稿的父目录由插件用 `mkdirSync` 递归创建，失败留到写草稿时以工具错误暴露。

## 产出文件检查

- 挂点与守卫同源，在「工具写入落盘后」：先让链路继续，只在写入真的成功、且后续监听器没有否掉这次写入之后追加提醒——警告永远不阻止写入。
- 提醒以 notice 形式的上下文消息挂出，摘要分别是「Spec mode: AGENTS.md 检查」与「Spec mode: 文档检查 <文件名>」。

「这次写的是不是产出文件」由目标路径判定：

| 目标 | 判定 |
| --- | --- |
| 任何目录下的 `AGENTS.md` | 规范文件——不论在哪个目录，宿主就按这个文件名读基线 |
| 路径里有一段是 `docs` 的 `.md` 文件 | 文档 |
| `edit`、失败的写入、其它文件 | 不检查 |

草稿本身是 `docs` 下的 `.md`，但被显式排除：它每轮都写、落盘时删除，是中间产物而不是产出文件。

### 检查项与触发条件

| 检查 | 判据 | 什么时候挂出 |
| --- | --- | --- |
| 规范文件行数预算 | 内容超过 200 行 | 任何一次写 `AGENTS.md`，不判模式 |
| 文档规则块齐全 | 六个要点都能在文里找到：改代码前同步过时文档、规则文件只放索引与规范不写进度、文档只写结论不解释、信息密度极高、代码跟着复现步骤、决策只记结论 | 仅 spec 工作期间 |
| 规范文件没有进度类内容 | 标题、加粗标签或列表项命中进度词表；写了「不写进度」的规则句本身不算 | 仅 spec 工作期间 |
| 没有水分小节 | 标题或短加粗标签命中水分词表（导读、背景、动机、设计考量、小结、总结、综上之类）；写了禁令的规则句本身不算 | 仅 spec 工作期间 |
| 代码跟着复现步骤 | 见下 | 仅 spec 工作期间 |
| 决策只记结论 | 标题、加粗标签或列表项里命中拒绝词表（为什么不选别的、被否决的方案、替代方案之类）；写了禁令的规则句本身不算 | 仅 spec 工作期间 |

- 「spec 工作期间」= 模式开着，或本进程刚批准退出，或草稿还在盘上（手写 `/spec off` 后的落盘）。三种都不满足时，产出文件检查只剩规范文件行数预算一项。
- 「只写结论、不解释」与「信息密度极高」没有对应检查：这两条是整篇的语义判断，只看结构判不了。要求落在提示词里，靠模型自己通读；机器能判的只有「水分小节」这一项标题级检查。

### 代码的复现步骤判到什么程度

文档里可以有代码，但代码只能当「读者要照着做的步骤」。判据是围栏块，不看行内反引号。

| 围栏块 | 处理 |
| --- | --- |
| 命令块：块里每一行都是命令，或以 `-`、`\|`、`>`、`#` 开头的续行 | 放行——它本身就是操作步骤。命令按行首判定，可带 `sudo`、`./`、`../` 前缀；斜杠命令也算 |
| 图形块：围栏标签是 mermaid、dot、graphviz、plantuml、puml、text、txt、ascii，或块里出现箭头与框线字符 | 放行——图形不是代码，插件不要求项目写图 |
| 其余围栏块 | 看块前 3 行、块后 6 行，找「写进哪个文件 / 执行什么 / 看到什么」这类说法；找不到就挂一条提醒，只报第一个命中的块 |
| 空块 | 不检查 |

近似性是有意的：只看结构行与围栏块，不评价整篇读不读得懂。

## 注入机制

访谈协议走系统提示词段落，不走消息注入：

| 项 | 取值 |
| --- | --- |
| 段落名 | `spec:policy` |
| 排序位置 | 取计划模式策略段（`PLAN_POLICY`）的位置 |
| 未激活时 | 渲染空串，宿主丢弃空段落——不激活就零 token |
| 段落文本 | 每次装配时求值的提供者，不是快照，进出模式立即生效 |
| 提供者抛异常 | 贡献空串（抛出去会让整个装配失败） |

用户可见的两条消息走代理的注入与转向通道：

| 场景 | 效果 |
| --- | --- |
| 进入命令带想法 | 想法（以及附件）成为这一轮的用户消息并唤醒驱动 |
| 进入命令无参 | 什么都不提交，只切模式 |
| 退出命令 | 只入收件箱，不唤醒；下一轮模型才知道模式已退出 |

- 进入命令无参时不合成起轮消息：裸 `/spec` 之后没有任何一轮被唤醒，访谈从用户真正写下的东西开始——命令后面的想法，或他随后发的第一条普通消息（那一轮装配已带上策略段落）。命令回执只说模式开了、草稿在哪。
- 用户消息由插件自己构造（随机标识加深冻结），不引宿主提供的消息工厂。

## 命令实现

命令通过可选服务注入注册（该服务缺席时插件仍能激活，只是进不去模式）。处理器顺序：

| 顺序 | 条件 | 动作 |
| --- | --- | --- |
| 1 | 参数是 `off`、已提交状态为假 | 回「未开启」，别的都不做 |
| 2 | 参数是 `off`、已提交状态为真 | 注入退出提醒（工作树恢复可写、按顺序落盘），回执里带草稿路径 |
| 3 | 不是 `off`、已提交状态为假、计划模式活跃 | 回错误，状态不变 |
| 4 | 不是 `off` | 清掉本会话的退出旁路、确保草稿父目录存在 |
| 5 | 有想法或附件 | 转向提交（附件在前、文本在后） |
| 6 | 两者都没有 | 什么都不提交，只切模式；回执说工作树只读、直接发消息即可开始访谈 |

状态一律由命令开始与命令结束这两条会话事件承载，处理函数自己不写任何状态。

## 退出确认

退出确认工具常驻注册：进出模式不改变工具目录，只换提示词段落。执行顺序：

| 顺序 | 条件 | 结果 |
| --- | --- | --- |
| 1 | 调用没有关联代理 | 抛错 |
| 2 | 该会话不在模式里 | 抛错 |
| 3 | 组合里没有提问通道 | 抛错——失败即关，让用户走退出命令 |
| 4 | 弹确认框，带上这次调用的中止信号 | 按用户动作分流，见下表 |

| 用户的动作 | 结果 |
| --- | --- |
| 关掉面板 | 抛错：模式保持开启，停下等他的消息 |
| 选「退出并落盘」 | 加进进程内旁路，返回「已退出」加草稿路径 |
| 选「继续访谈」或写自定义文本 | 抛错：模式保持开启、工作树仍只读，明确「不要重复调用本工具」；自定义文本原样带回 |

- 批准的判定：答案里恰好选中「退出并落盘」一项，且没有自定义文本。
- 抛错即工具结果带错误标记，投影据此清掉「正在评审的退出调用」，已提交状态不变——「用户拒绝」不需要额外的事件类型。
- 中止信号按鸭子类型判（看错误对象上的代码字段是不是 `ASK_CANCELLED`），不用 `instanceof`，也就不 import 宿主的提问包。
- 工具输出是「已退出」加草稿路径两项；渲染函数直接给出落盘三步：`AGENTS.md` → `docs/*.md` → 删除草稿。

## 设计约束

| 约束 | 内容 |
| --- | --- |
| 状态由会话日志推导 | 插件不写自己的事件类型 |
| 零宿主包依赖 | 只 import 仓库内的模块；需要宿主工具时按等价实现内联 |
| 工具定义手写 | 注册时只校验输出形状与输出 schema 的 JSON 子集，参数 schema 直接透给模型；本工具无参数 |
| 手动退出不弹确认 | 确认框只留给模型发起的收尾；`/spec off` 直接退出，退出后同样按顺序落盘 |
| 只做宿主半边 | 不声明客户端可见的投影视图；状态指示需要客户端插件消费投影视图，留作后续 |
| 图标用显式颜色 | 图标以数据地址渲染，拿不到宿主样式里的颜色 |
| 结构性问题用代码拦，内容质量用提示词或警告 | 内容质量无法机器判定，检查只挂提醒、不阻止写入 |

## 宿主接口面

全部是运行期从上下文、代理、会话上取的实例成员，没有 import：

| 来源 | 用到什么 |
| --- | --- |
| 投影服务 | 注册投影单元、按会话取状态 |
| 提示词服务 | 注册段落、取计划模式策略段的排序位置 |
| 命令服务 | 注册命令（标识、名字、描述、输入提示、处理函数） |
| 工具服务 | 注册工具、挂守卫、监听「工具写入落盘后」事件 |
| 上下文事件 | 「工具写入落盘后」、「会话创建」两个事件 |
| 可选服务 | 注入命令服务、取计划模式状态、取提问通道 |
| 代理 | 会话、注入消息、转向提交 |
| 会话 | 会话头里的工作目录、来源、嵌套深度 |
| 工具执行记录 | 关联代理、工具名、入参、中止信号 |
| 提问通道 | 提问请求 → 回答（每题的选中项与自定义文本） |

- 必需注入是工具、系统提示词、会话投影三项；命令、计划模式、提问通道都是运行期可选，缺席时插件仍能激活。
- 宿主升级后这些签名可能变动，核对时跑 docs/交接文档.md 的「验证清单」。

## 已知边界

- 用 shell 写文件不拦：守卫只覆盖结构化的写原语（`write`、`edit`）。
- 提醒只在 spec 工作期间挂出，且只做近似判定（结构行、围栏块）。
- 草稿删除保护依赖存在删除、移动、改名这类工具，当前工具集下休眠。
