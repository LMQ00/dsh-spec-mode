# Spec Mode 实现逻辑

这份文档回答一个问题：这个插件的代码为什么长成现在这样。读者是要改它的人——读完你会知道每个
模块管什么、状态从哪里来、守卫按什么判、产出文件的提醒在什么时候挂出，以及哪些边界是刻意留下
的。不需要先读别的文档。

三句结论先摆出来：插件不自己存状态，状态全部从会话日志推导；工作树的写权限由守卫按会话拦截；
访谈收尾由模型发起一次用户确认，确认通过才落盘。

## 模块划分

| 文件 | 管什么 |
| --- | --- |
| index.js | 装配入口。注册投影、提示词段落、进入命令、退出确认工具、只读守卫、产出文件提醒、跨会话提醒 |
| state.js | 状态类型、会话投影单元、草稿路径解析 |
| guard.js | 路径分类谓词、工具入参里的路径提取 |
| advisories.js | 产出文件的软约束文案：规范文件行数、文档规则块、代码的复现步骤、首段白话导读、决策只记结论 |
| prompt.js | 注入文本：访谈协议、跨会话提醒 |

依赖方向单向：装配入口依赖其余四个，其余四个互不依赖。被依赖的四个模块都是纯函数或纯数据，
自测脚本直接测它们，不需要宿主。

## 状态模型

状态只有三样东西：

| 状态 | 含义 |
| --- | --- |
| 是否启用 | 已提交的启用状态，布尔 |
| 正在执行的那次选择 | 当前这条进入命令想把它切成什么状态；没有正在执行的就是空 |
| 正在评审的退出调用 | 退出确认工具这次调用的标识；没有在评审就是空 |

注册为会话投影单元，**只有宿主半边**：不声明客户端可见的视图，所以不参与客户端拿到的投影快照，
但会被投影缓存正常存档与恢复。

### 状态一律从既有事件推导

插件不自己往会话日志里写状态事件，只做一次纯同步折叠：

| 会话日志里出现 | 折叠结果 |
| --- | --- |
| 进入命令开始 | 记下「这次选择」：参数是 off 就是想关，否则就是想开 |
| 进入命令结束 | 成功才提交成新状态，失败就丢弃；两种情况都清掉「这次选择」 |
| 退出确认工具被调用 | 记下这次调用标识 |
| 这次调用的结果回来 | 失败（用户没批准）就清掉标识、状态不变；成功就整体退出模式 |
| 其它任何事件 | 返回同一个状态引用 |

为什么不能自建事件类型：会话事件的类型表虽然可以扩展声明，但**读路径**只认宿主那份已知类型
清单，除非事件信封自带「可忽略」标记，而会话日志的追加入口设不了这个标记。写进去的结果是这份
日志之后打不开。所以状态全部由既有事件推导——这是硬约束，不是风格偏好。

折叠函数对无关事件必须返回**同一个引用**（投影契约要求按引用相等判断有没有下游工作），状态本身
是纯 JSON（缓存的前提）。

### 有效状态与已提交状态

两个读法，不能混用：

| 读法 | 含义 | 谁用 |
| --- | --- | --- |
| 有效状态 | 「正在执行的那次选择」优先，没有则用已提交状态 | 守卫、提示词段落、退出确认工具——问「这一刻算不算在模式里」 |
| 已提交状态 | 只看已提交那一项 | 进入命令的处理函数——问「这条命令进来之前是什么状态」 |

**命令记录在处理器之前入日志**（先追加开始、再调处理函数、最后追加结束）。所以处理函数执行期间
「正在执行的那次选择」已经是本次的选择，而「已提交状态」还是旧值。实测踩到过：

- 退出命令若用有效状态判「本来是否开启」，会得到「没开启」，错报未启用；
- 进入命令若用有效状态判「是否已在模式里」，会因为本次选择是想开而跳过计划模式的互斥检查。

自测脚本里有一条断言专门锁这个不变量。

### 进程内的退出旁路

按会话记的进程内集合：退出确认工具批准后加进去，再次进入模式时移除。

它只解决一件事：批准退出的结果入日志后，**同一轮**紧接着的规范文件写入不能被「还没折叠到」的
投影拦下。持久真相仍是那条结果的折叠——旁路只影响本进程的即时判定，进程重启后由日志恢复。

## 生命周期绑定

| 时机 | 做什么 |
| --- | --- |
| 会话创建 | 草稿提醒：仅根会话、且当前未启用、且草稿非空；是否已落盘由模型对照产出文件判定 |
| 工具写入落盘后 | 产出文件检查：行数预算、文档规则块、代码的复现步骤、首段白话导读、决策只记结论 |

投影本身不自己订阅会话事件：注册之后由框架驱动折叠，所以没有需要清理的订阅。其余注册（工具、
守卫、提示词段落、事件、可选服务注入）都挂在插件自己的生命周期上，卸载即回收。

子代理的判定看会话头：来自子代理或嵌套深度大于零的都不是访谈者，不发提醒。子代理的模式状态
天然为假（它的日志里没有进入记录），所以守卫也不会拦它。

## 工具守卫

守卫是**同步、单调**的检查：返回文案即拒绝，返回空即放行；它排在所有「写入前」监听器之后，
所以没有后续监听器能把拒绝翻回允许。判定顺序：

1. 调用没有关联会话 → 放行。
2. 该会话的有效状态为假 → 放行。
3. 工具名以删除、移动、改名开头 → 只看草稿：命中草稿就拒绝（草稿在合并进规范文件前不可删改），
   否则放行。
4. 工具名不是结构化的写原语（写入、编辑）→ 放行。
5. 其余情况：入参里任何一个路径被判成工作树 → 拒绝。

守卫注册在**全局**上下文上（不是单个代理的上下文），按调用所属的会话取状态——这正是「状态按
会话分键」的落点。

### 路径判定

| 判定的输入 | 结论 |
| --- | --- |
| 路径为空，或匹配「协议名后跟两斜杠」的形式 | 协议路径——设备地址，一律放行 |
| 按会话工作目录解析相对路径时抛错 | 工作树——失败即关 |
| 解析结果等于草稿的绝对路径 | 草稿 |
| 其余 | 工作树 |

**草稿只匹配草稿文件本身，不匹配它的父目录。** 草稿住在项目的文档目录里，目录级放行等于把真实
文档目录开了写权限。父目录由插件自己直接创建，不经过工具层，所以不需要放行。

相对路径按会话工作目录解析。宿主写文件时可能改用沙箱的工作区根作基准，两者不同时相对路径会指向
另一个文件——协议因此要求一律写绝对路径。这是已知边界，不是疏漏。

入参里的路径按工具用过的那几种键名收集（主键、驼峰别名、复数形式），不认得的键就当没有路径。

## 草稿路径解析

锚点 = 从会话工作目录往上找到的最近的版本库目录，找不到就用工作目录本身；草稿 = 锚点下的文档
目录里的访谈草稿。

锚点规则**故意**与宿主的指令文件读取机制保持一致（它认的项目标记默认只看版本库目录，找不到就用
会话工作目录），这样草稿和指令文件落在同一个项目里。

原插件还会认「项目本地配置目录」，并专门排除用户全局配置根。DSH 没有对应的项目标记（harness
主目录不是项目标记），所以这条分支不引入。

## 产出文件检查

挂点与守卫同源：工具写入落盘后先让链路继续，只在**写入真的成功**之后追加提醒——警告永远不阻止
写入。

「这次写的是不是产出文件」由目标路径判定：

| 目标 | 判定 |
| --- | --- |
| 任何目录下的规范文件（AGENTS.md） | 规范文件；不论在哪个目录，宿主就按这个文件名读基线 |
| 路径里带文档目录的 Markdown | 文档 |
| 编辑原语、失败的写入、其它文件 | 不检查 |

检查项分四组，触发条件不同：

| 检查 | 判据 | 何时挂出 |
| --- | --- | --- |
| 规范文件行数预算 | 内容超过 200 行 | 任何一次规范文件写入，不判模式 |
| 文档规则块齐全 | 规则块的五个要点（过时同步、代码只在要人照做时出现且跟着复现步骤、白话导读、讲流程画真的图、决策只记结论）都能在文里找到 | 仅 spec 工作期间 |
| 代码的复现步骤 | 见下 | 仅 spec 工作期间 |
| 首段白话导读 | 第一个小节标题之前有没有一段 24 字以上、不含反引号与路径的纯白话 | 仅 spec 工作期间 |
| 决策只记结论 | 标题、加粗标签或列表项里命中拒绝词表 | 仅 spec 工作期间 |

「spec 工作期间」= 模式开着，或本进程刚批准退出，或草稿还在盘上（手写退出命令后的落盘）。不判
模式的话，装了插件但没用 spec mode 的项目写自己的文档会被无端提醒。

草稿被排除在外：它每轮都写、落盘时删除，是中间产物而不是产出文件。

### 「代码的复现步骤」判到什么程度

文档里可以有代码，但代码只能当「读者要照着做的步骤」。判据是**围栏块**：

- **命令块放行**：围栏块里每一行都是命令、参数续行或 shell 注释——它本身就是操作步骤。命令的判定
  按行首是不是已知的可执行名，句子中间出现的「可执行名 + 目标文件」也整体跳过；斜杠命令算命令。
- **图块放行**：围栏标签是图表格式（流程图、时序图之类），或块里出现箭头与框线字符——图不是代码，
  它另配白话读图说明。
- **其余围栏块要复现说明**：看块前后各几行，找「写进哪个文件 / 执行什么 / 看到什么」这类说法；找
  不到就报——这段代码是用来讲实现的，而实现逻辑应该用白话讲清。

只看围栏块，不看行内反引号：行内提到一个名字、一个命令读不出「是讲实现还是给步骤」，硬判只会误报。

近似性是有意的：光看首段与结构行，不评价整篇读不读得懂；误报只挂一条提醒。

## 注入机制

访谈协议走**系统提示词段落**，不走消息注入：

- 段落名是 spec 的策略段落，排序位置取计划模式策略段的位置；
- 未激活时渲染空串，宿主会丢弃空段落——不激活就零 token；
- 段落文本是每次装配时求值的提供者，不是快照，所以进出模式立即生效；
- 提供者包了异常兜底：抛异常会让整个装配失败，这里选择贡献空串。

用户可见的两条消息走代理的注入与转向通道：

| 场景 | 效果 |
| --- | --- |
| 进入命令带想法 | 想法成为这一轮的用户消息并唤醒驱动 |
| 进入命令无参 | 什么都不提交，只切模式 |
| 退出命令 | 只入收件箱，不唤醒；下一轮模型才知道模式已退出 |

进入命令无参时**不合成起轮消息**：命令面本身不产生模型消息，所以裸 `/spec` 之后没有任何一轮
被唤醒，访谈从用户真正写下的东西开始——命令后面的想法，或他随后发的第一条普通消息（那一轮的
装配已经带上策略段落）。这样命令回执只说「模式开了、草稿在哪」，不会替用户开题。

用户消息由插件自己构造（随机标识 + 深冻结），等价于宿主提供的消息工厂，但省掉一个依赖。

## 命令实现

命令通过可选服务注入注册（该服务缺席时插件仍能激活，只是进不去模式）。处理器顺序：

1. 参数是 off：已提交状态为假就回「未开启」；否则注入退出提醒并回执。
2. 不在模式里时查计划模式是否活跃，活跃则回错误，状态不变。
3. 清掉本会话的退出旁路、确保草稿父目录存在。
4. 有想法或附件就转向提交；否则什么都不提交（裸命令只切模式）。

状态一律**由命令开始与命令结束这两条会话事件承载**，处理函数自己不写任何状态——这是「内存状态
始终由会话日志派生」的落点，避免两处真相。

## 退出确认

退出确认工具常驻注册，不做按需加载：进出模式只换提示词段落，不换工具目录，缓存前缀因此更稳；
也避免「收尾这种必需步骤要靠搜索命中」。执行顺序：

1. 调用没有关联代理 → 抛错。
2. 该会话不在模式里 → 抛错。
3. 组合里没有提问通道 → 抛错（失败即关，让用户走退出命令）。
4. 弹确认框，带上这次调用的中止信号。
   - 用户关掉面板 → 抛错：保持开启，停下等他的消息；
   - 选了退出并落盘 → 加进进程内旁路，返回退出成功；
   - 其它（继续访谈、或自定义文本） → 抛错：明确「不要重复调用本工具」。

抛错即工具结果带错误标记，投影据此清掉「正在评审的退出调用」、已提交状态不变——「用户拒绝」
不需要额外的事件类型。

中止信号按鸭子类型判（看错误对象上的代码字段），不用 instanceof：后者要求 import 宿主的提问
包，而本插件刻意零依赖。

工具的输出是「已退出」加草稿路径两项，渲染函数直接给出落盘三步，避免模型凭记忆排序。

## 设计约束

- **状态由会话日志推导**，插件不写自己的事件类型（上面那条硬约束的直接后果）。
- **零宿主包依赖**：profile 是链接进来的，Node 从包自身位置解析 import；引了宿主包就得在包清单里
  声明依赖，等于装第二份运行时。需要宿主工具时按等价实现内联。
- **工具定义手写**：注册时只校验输出形状与输出 schema 的 JSON 子集，参数 schema 直接透给模型；
  参数校验由宿主的工具工厂自己做，本工具无参数，不需要。
- **手动退出不弹确认**：确认框留给模型发起的收尾，那才是真正需要用户裁决的一步。
- **只做宿主半边**：状态指示需要客户端插件消费投影视图，留作后续。
- **图标用显式颜色**：图标以数据地址渲染，拿不到宿主样式里的颜色。
- **结构性问题用代码拦，内容质量用提示词或警告**：内容质量无法机器判定，误报代价却由用户承担。

## 宿主接口面

全部是运行时从上下文、代理、会话上取的实例成员，没有 import：

| 来源 | 用到什么 |
| --- | --- |
| 投影服务 | 注册投影单元、按会话取状态 |
| 提示词服务 | 注册段落、取计划模式策略段的排序位置 |
| 命令服务 | 注册命令（标识、名字、描述、输入提示、处理函数） |
| 工具服务 | 注册工具、挂锅守卫 |
| 上下文事件 | 「工具写入落盘后」「会话创建」两个事件 |
| 可选服务 | 注入命令服务、取计划模式状态、取提问通道 |
| 代理 | 会话、注入消息、转向提交 |
| 会话 | 会话头里的工作目录、来源、嵌套深度 |
| 工具执行记录 | 关联代理、工具名、入参、中止信号 |
| 提问通道 | 提问请求 → 回答（每题的选中项与自定义文本） |

宿主升级后若这些签名变动，先跑交接文档里的验证清单。

## 已知边界

- 用 shell 写文件不拦：守卫只覆盖结构化的写原语。
- 提醒只在 spec 工作期间挂出，且只做近似判定（首段、结构行、围栏块）。
- 草稿删除保护依赖存在删除、移动、改名这类工具，当前工具集下休眠。
- 相对路径草稿按会话工作目录判定，与沙箱工作区根不同基准时是已知边界。
- 计划模式互斥是单向的：本插件知道计划模式，反过来不知道。
