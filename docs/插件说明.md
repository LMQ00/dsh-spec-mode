# Spec Mode 插件说明

这份文档回答：`/spec` 模式做什么、怎么用、拦什么不拦什么、界面出现在哪、有哪些限制。

## 包与装配

| 项 | 内容 |
| --- | --- |
| 包目录 | 仓库根目录 |
| 入口 | 仓库根目录的 `index.js`：接收插件上下文，把投影、提示词段落、命令、工具、守卫挂上去 |
| 依赖 | 只用 Node 自带的加密、文件、路径三类模块；不装宿主运行时包，只靠 profile 自身解析 |
| 安装形态 | 以 link 方式挂进 web profile 的 bundle 列表；加载器里的行为名是 `include:spec-mode` |
| 用到的宿主能力 | 工具、系统提示词段落、会话投影是必需项；命令与提问通道可选，缺了照样激活，只是没有进出方式 |

## 命令与状态

在网页输入框直接输入，回执见下表：

```sh
/spec
/spec 做一个导出功能
/spec off
```

未启用时进入一律做三件事：解析草稿路径、建 `docs/` 目录、把状态写进会话日志，再注入访谈协议（走系统提示词段落，不展开在对话里）。

| 当前状态 | `/spec` 的行为 | 回执 |
| --- | --- | --- |
| 未启用 + 无参 | 只进入模式，不提交任何消息；访谈从用户随后发的第一条消息开始 | `Spec mode on. 工作树只读；直接发消息即可开始访谈。草稿：<草稿路径>` |
| 未启用 + 带想法或附件 | 进入模式，并把想法（连附件）作为这一轮的用户消息提交，访谈立刻开始 | `Spec mode on. 草稿：<草稿路径>` |
| 已启用 + 带想法或附件 | 只把想法提交为这一轮的用户消息 | 同上 |
| 已启用 + 无参 | 只回执，不提交消息；模型在用户下一条消息里继续访谈 | `Spec mode on. 工作树只读；直接发消息即可开始访谈。草稿：<草稿路径>` |
| 已启用 + `off` | 退出，工作树恢复可写，草稿保留；同时注入一行提示，让模型接着落盘 | `Spec mode off. 草稿保留在 <草稿路径>` |
| 未启用 + `off` | 什么都不做，状态不变 | `Spec mode 未开启。` |
| 计划模式活跃 + 进入 | 拒绝进入（只在未启用时检查），状态不变 | `Exit plan mode first.` |

状态从会话日志折叠得出，恢复、分叉、重放都能还原这个会话的模式与草稿。

- 访谈结束不需要用户手动退出：模型调用 `spec_resolve` 弹确认框。
- `/spec off` 是手动退出的备用入口。
- 会话启动时草稿还在盘上、而本会话没进过模式：注入一行提示——读它并对照 `AGENTS.md` 与 `docs/`，已被取代就删掉、未被取代才接着访谈；要恢复只读守卫就运行 `/spec`。子代理会话不给这条提示。

## 访谈期间

工作树只读，唯一可写目标是草稿。

| 项 | 内容 |
| --- | --- |
| 草稿路径 | `docs/spec-draft.md` |
| 锚点 | 会话工作目录里最近一个带 `.git` 的目录；找不到就用会话工作目录本身 |
| 路径写法 | 一律用绝对路径；相对路径按会话工作目录解析，判不成草稿就会被拦下 |
| 草稿小节 | 推断出的结论进「假设」，未决项进「未决」；每轮回答立刻写进草稿，不攒到访谈结束 |
| 已确定的字段 | 不重问；用户追加时增量合并 |
| 提问 | 一次问几个不限；每个问题都在补用户侧信息，不是确认模型已形成的判断 |
| 回述确认 | 每轮用自己的话复述理解，含推出但用户没明说的结论，让他确认或纠正 |
| 七项字段 | 目标与验收 / 技术选型 / 实现路径 / 边界条件 / 验证方式 / 开发规范 / 文档；全部覆盖且用户确认过回述，才算访谈完成 |
| 每轮结尾 | 输出一行 `已定：… ｜ 待定：… ｜ 假设：…` |

## 拦截与提醒

检查只认 `write` 工具的成功写入，对象是 `AGENTS.md`（不限位置）与路径里带 `docs` 目录的 `.md` 文件；`edit` 不触发。所有提醒都不阻止写入。

| 约束 | 强度 | 触发条件 |
| --- | --- | --- |
| 工作树写入 | **阻止** | `write`、`edit` 的目标路径不是草稿；`local://` 这类 `scheme://` 设备路径与空路径放行 |
| 模式开启期间写 `AGENTS.md` 或 `docs/*.md` | **阻止** | 同上，它们是工作树写入；落盘在退出后进行 |
| 删除、改名草稿 | **阻止** | 工具名以 `delete`、`remove`、`move`、`rename` 开头，且目标命中草稿；命中别的路径放行 |
| 退出模式 | 用户确认 | 退出确认工具走宿主的提问通道 |
| 计划模式活跃时进入 | **阻止** | 读宿主计划模式的启用状态；该服务缺席时静默跳过 |
| `AGENTS.md` 超过 200 行 | 警告 | 每次成功写入 `AGENTS.md` 后，不判模式 |
| `AGENTS.md` 缺文档规则块 | 警告 | 落盘期间写入时；六条规则缺哪条报哪条 |
| `AGENTS.md` 里写了进度类内容 | 警告 | 落盘期间；标题、加粗标签或列表项命中进度词表（现状 / 待办 / 下一步 / 里程碑 / 变更记录 / roadmap / TODO……）就报，规则句本身不算 |
| 文档里出现水分小节 | 警告 | 落盘期间；标题或短加粗标签命中「导读 / 背景 / 动机 / 设计考量 / 小结 / 总结 / 权衡」一类词 |
| 代码块没有复现步骤 | 警告 | 落盘期间；非命令行、非图形的围栏代码块，前后几行找不到「写进哪个文件 / 执行什么 / 看到什么算成功」的说法 |
| 文档里写了被否决方案 | 警告 | 落盘期间；标题、加粗标签或列表项命中拒绝词表，表格行不算 |
| 访谈草稿 | 不检查 | 草稿是中间产物，落盘时删除，检查前按路径排除 |
| 用 shell 写文件 | 不拦 | 代码只守卫结构化写原语 |
| 提问方式、理解质量、落盘顺序 | 提示词 | 没有代码检查 |

提醒的挂出时机：只有 `AGENTS.md` 的行数预算不判模式；其余提醒只在模式开着、本轮刚批准退出、或草稿还在盘上时出现，并排除草稿本身。装了插件但没在用 spec mode 的项目，写自己的文档不会被提醒。

`local://` 这类设备路径一律放行。

## 退出与落盘

落盘在退出 spec mode 之后做，按顺序不跳步：

| 顺序 | 写什么 | 内容约束 |
| --- | --- | --- |
| 1 | `AGENTS.md` | 只放文档索引（每份文档的仓库相对路径 + 何时读）与可证伪的开发规范规则（每条标注代码强制还是提示词）。不写开头介绍句，不写现状、进度、待办、下一步、里程碑、变更记录，不设项目简介、语言风格这类章节 |
| 2 | `docs/*.md` | 只写实际存在的文档；访谈里浮现的产品特性（行为边界、对外契约、状态机约束、结构决策）写这里；只写结论与硬事实、不解释，信息密度极高，代码能不出就不出、要给就跟着复现步骤；决策只记结论。文档集合由访谈第 7 项定，写不出内容的类型不写、不留占位文件 |
| 3 | 删除草稿 | 留着会变成第二份真相来源 |

归属判据：这条规则换了实现就失效吗？会 → 产品特性，进 `docs/`；不会 → 开发规范，进 `AGENTS.md`。

文档规则块固定写进 `AGENTS.md`（是一块规则，不是新章节），六条缺一不可：改代码前同步过时文档 / 只放索引与规范、不写进度 / 文档只写结论、不解释 / 信息密度极高 / 代码跟着复现步骤 / 决策只记结论。

确认框的四个出口：

| 用户选择 | 结果 |
| --- | --- |
| 退出并落盘 | 退出模式、工作树可写；工具结果指示模型在同一轮按上表落盘 |
| 继续访谈 | 模式不变、工作树仍只读；工具结果写明不要重复调用，等用户补充需求 |
| 关掉确认框 | 模式不变；工具调用报错，告诉模型用户在插话，停下等消息 |
| 组合里没有提问通道 | 模式不变；工具调用报错，让用户运行 `/spec off` |

在非 spec 模式下调用退出确认工具会直接报错。

## 界面

| 界面 | 表现 |
| --- | --- |
| 输入框的命令菜单 | 一行 `spec`，描述取命令自带的描述；**没有图标** |
| 命令执行回执 | 每种状态的原文见「命令与状态」的回执列 |
| 对话流 | 只出现工具调用与用户消息；协议文本走系统提示词段落，不占对话；裸 `/spec` 不提交任何消息，只留一条命令回执；退出回执与跨会话草稿提醒以一行提示注入 |
| 设置里的插件页 | 卡片、列表与详情读插件元数据里的图标与多语言文案，图标取包里的 `icon.svg`；元数据已实测读取成功，页面渲染未目视确认 |

## 已知限制

- **用 shell 写文件不拦**：重定向写文件能绕过守卫。
- **互斥是单向的**：本插件会拒绝在计划模式活跃时进入；计划模式不知道 spec mode 的存在。当前 profile 里计划模式被禁用，这条检查休眠。
- **子代理不受限**：状态按会话分别记录，子代理会话没有进入记录，所以不会被拦。
- **草稿删除保护可能休眠**：当前工具集里没有以删除、移动、改名开头的工具，该分支只在存在这类工具时生效。
- **落盘仍是模型驱动的**：退出确认工具只保证「退出要经用户确认」，落盘顺序靠协议与工具结果文本约束，没有代码校验。
- **提醒是近似判定**：只查得动结构，查不了「整篇读不读得懂」，每类最多一条，误报不阻止写入。
- **提醒只在 spec 工作期间挂出**：`AGENTS.md` 的行数预算不判模式，其余提醒只在模式开着、本轮刚批准退出、或草稿还在盘上时出现，并排除草稿本身。
- **没有界面状态指示**：状态栏不显示 spec；本插件只有宿主半边，客户端半边未实现。
- **没有配置项**：协议文本、草稿文件名、行数预算都是代码常量。
- **相对路径草稿按会话工作目录判定**：宿主写文件时可能以沙箱的工作区根为基准，两者不同时，`docs/spec-draft.md` 这个写法可能被判成草稿而实际写到别处；协议因此要求一律用绝对路径，改这块要一起看路径判定的实现。
