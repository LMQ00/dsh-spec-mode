# 002 规则与权限

这份文档决定谁能发起、什么动作被允许、什么被拒绝。它建立在 [001 领域模型](001-domain.md) 的概念上：草稿、图集、图、模式、落盘。

## 两条路径

| 路径 | 谁发起 | 写什么 | 怎么被约束 |
| --- | --- | --- | --- |
| 访谈 | 用户输入 `/spec` | 模型只能写草稿 | 工具守卫拦下其它一切写入 |
| 落盘 | 模型调 `spec_resolve`，用户点「退出并落盘」 | 插件写图集、删草稿 | 先校验，再确认，后写盘 |

两条路径的权限不重叠：访谈期间模型写不了图集，落盘只由工具执行、模型交的只是参数。

访谈之外还有第三条入口，由人发起：流程图页的表单与 `flow_write` 工具。它们跑同一套校验，并且 `flow_write` 在模式开着时被拒绝。

## 谁的写入被拦

守卫只看 `write` 与 `edit` 两个工具，以及名字以 `delete`、`remove`、`move`、`rename` 开头的工具。

| 目标 | `write` / `edit` | `delete` / `remove` / `move` / `rename` |
| --- | --- | --- |
| 草稿 `.spec/draft.md` | 放行 | 拒绝 |
| 工作树里任何其它路径 | 拒绝 | 放行 |
| `local://`、`artifact://` 这类 `scheme://` 路径 | 放行 | 放行 |
| 空字符串或解析失败 | 放行 | 放行 |

空路径按 `protocol` 分类，所以解析失败的输入不会因为「不知道怎么判」而被当成工作树拒绝；真正的写入由工具自己报错。

## 工具、命令与路由

| 名字 | 谁调 | 模式开着时 | 模式关闭时 |
| --- | --- | --- | --- |
| `/spec` | 人 | 只提交这一轮消息，或只回执 | 进入模式 |
| `/spec off` | 人 | 退出，草稿保留 | 什么都不做，回执「未开启」 |
| `spec_resolve` | 模型 | 校验 → 确认框 → 写盘 → 退出 | 报错 |
| `flow_read` | 模型 | 可用 | 可用 |
| `flow_write` | 模型 | 拒绝 | 可用 |
| `/spec/flows/mermaid.js` | 页面 | 可用 | 可用 |
| `/spec/flows/list`、`chart` | 页面 | 可用 | 可用 |
| `/spec/flows/save`、`create`、`delete` | 页面 | 可用 | 可用 |

`flow_write` 在模式里被拒是因为访谈中的改动只能经确认框落盘，否则用户刚确认过的内容会被悄悄覆盖。图集路由不受模式影响：页面保存时用修订号比对盘上版本，冲突时返回 409。

## 进入的条件

`/spec` 只有在计划模式不活跃时才生效。

| 条件 | 结果 | 回执 |
| --- | --- | --- |
| 计划模式活跃 | 拒绝进入，状态不变 | `Exit plan mode first.` |
| 未启用、无参数 | 进入模式，不提交消息 | `Spec mode on. 工作树只读；直接发消息即可开始访谈。草稿：<路径>` |
| 未启用、带想法 | 进入模式，想法成为这一轮用户消息 | `Spec mode on. 草稿：<路径>` |
| 已启用、带想法 | 只提交这一轮用户消息 | `Spec mode on. 草稿：<路径>` |
| 已启用、无参数 | 只回执 | `Spec mode on. 工作树只读；直接发消息即可开始访谈。草稿：<路径>` |

裸 `/spec` 不合成消息：访谈从用户真正写下的内容开始。这条规则只约束进入那一次调用。

## 强度表

| 约束 | 强度 | 成立条件 |
| --- | --- | --- |
| 工作树写入 | 阻止 | 模式对当前会话生效；工具是 `write` 或 `edit`；目标分类为 `working-tree` |
| 删改草稿 | 阻止 | 模式生效；工具名命中破坏性前缀；目标分类为 `draft` |
| `spec_resolve` 参数不合格 | 阻止 | 文件四块、单图或整册的任何规则不通过；报行号、字段路径与图 id，不弹确认框 |
| `flow_write` 在模式里 | 阻止 | 会话的模式状态为生效 |
| 落盘写文件失败 | 阻止 | 目标不可写；报错带路径，模式不退出，草稿保留 |
| 计划模式活跃时进入 | 阻止 | 宿主计划模式服务报告 `active === true` |
| 确认框被关闭 | 阻止 | `userQuestions.ask` 抛 `ASK_CANCELLED`；模式保持 |
| 用户选「继续访谈」 | 阻止 | 选中的不是「退出并落盘」；模式保持，工作树仍只读 |
| `AGENTS.md` 超过 200 行 | 警告 | 每次成功的 `write` 且目标是 `AGENTS.md` |
| `AGENTS.md` 写了进度类内容 | 警告 | 同上；标题、加粗标签或列表项命中进度词表 |
| 用 shell 写文件 | 不拦 | 守卫只认结构化写原语 |

提醒一律不阻止写入，也不判模式：装了插件但没在用 spec mode 的项目，写自己的 `AGENTS.md` 一样会收到行数提醒。

## 保存的并发规则

页面保存时带上载入时拿到的修订号。修订号是那份 `.md` 整份文本的 sha256 前 16 位，标题、范围、源码、简报任何一处改动都换一个号。

| 盘上状态 | 结果 | HTTP |
| --- | --- | --- |
| 文件不存在 | 直接创建 | 200 |
| 修订号与盘上一致 | 写盘 | 200 |
| 修订号与盘上不一致 | 拒绝，回盘上当前的修订号 | 409 `conflict` |

`flow_write` 用同一个字段：传了 `revision` 且与盘上不一致就报错，不覆盖。

## 删除的规则

| 要删的图 | 结果 |
| --- | --- |
| 被别的图用模块框引用 | 拒绝，报出引用它的图 |
| 是唯一的一张 `overview` | 拒绝 |
| 都不是 | 删掉那一份 `.md` |

## 请求的准入

`/spec/flows` 下每个请求先过宿主的 `connection.requestRejection`，不通过时返回 403 `forbidden`，不碰文件系统。会话 id 从查询参数 `session` 取，取不到或找不到会话时返回 404 `no-session`。

`mermaid.js` 是例外：它发的是本机的渲染库，不带任何项目数据，所以不过准入，也不读会话。

请求体上限 4 MB，超出时返回 500，消息为 `请求太大`。
