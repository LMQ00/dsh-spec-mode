# Spec Mode 交接文档

这份文档是接手入口：它回答「我要做某件事，该读哪份文档的哪一节」。事实的唯一出处在
docs/插件说明.md 与 docs/实现逻辑.md，这里只放路由、当前状态、验证清单与坑。

接手的读者不需要懂这个插件的代码——先按「最短上手路径」跑一遍，再按需要跳进对应文档。

最后同步 2026-10-10。

## 最短上手路径

1. 在仓库根目录跑 node selftest.mjs，23 项断言全过 → 纯逻辑层没坏。
2. 打开网页界面，看插件列表里这一行是不是已启用、生命周期活跃。
3. 在输入框打斜杠，确认命令菜单里有 spec（无图标属预期）。
4. 进入模式后让模型写一个仓库文件，确认被守卫拦下（见验证清单第 4 条）。
5. 让模型调用退出确认工具，选「退出并落盘」，确认同一轮写出规范文件与文档、草稿被删除。

## 常见改动 → 改哪里

| 想改什么 | 改哪 |
| --- | --- |
| 访谈协议措辞、七项字段、落盘顺序、文档写法要求 | prompt.js |
| 草稿文件名或目录 | state.js 的草稿常量 |
| 草稿锚点规则 | state.js 的锚点查找 |
| 哪些工具被拦、放行范围 | index.js 的守卫注册 + guard.js 的路径分类 |
| 退出确认工具的行为与文案 | index.js 的工具注册 + prompt.js 的落盘小节 |
| 新增工具入参路径键 | guard.js 的路径键清单 |
| 拦截文案 | index.js 里守卫返回的文案 |
| 产出文件提醒项与阈值 | advisories.js |
| 跨会话提醒文案 | prompt.js 的草稿提醒 |
| 命令描述、回执文案、确认文案 | index.js 的命令注册与工具注册 |
| 图标 | icon.svg（用显式颜色，别跟随当前色；包清单里的图标字段指向它） |
| 投影状态字段或折叠语义 | state.js 的投影单元，**同时把状态版本号加一** |

包是链接进 profile 的，改文件后热重载会生效；若没生效，重开网页服务。改投影语义而不加版本号，
会让持久化缓存里的旧行被前向折叠成垃圾。

## 验证清单

手工步骤，逐条对应一个可观察结果。第 1 条已实测；第 2 条只验证了菜单里出现这一行，回执与后续
都还没跑；第 3 条起全部待验证。

1. **加载**：插件管理列表里这一行是已启用、生命周期活跃。
2. **进入**：输入框打斜杠，菜单里出现 spec（无图标，属预期）。
   - 裸 `/spec` → 回执说模式已开、工作树只读、草稿在哪，**对话里不出现任何消息、模型不启动**；
     随后随便发一条消息 → 模型按协议开始访谈。
   - `/spec 做一个 X` → 回执给出草稿路径，想法成为这一轮的用户消息，模型立刻开始访谈。
3. **草稿位置**：在**没有版本库目录**的目录里重复第 2 条 → 草稿落在该目录的文档目录下，不是
   落在用户主目录里。
4. **守卫**：让模型写一个仓库文件（例如仓库根的说明文件）→ 工具返回「工作树只读」的文案，
   确认文件未创建。
5. **放行边界**：让模型写文档目录里的另一个 Markdown → 同样被拦（只有草稿本身可写）。再让它写
   草稿的绝对路径 → 成功。
6. **互斥**：本 profile 里计划模式是禁用的，这条要先启用计划模式那一行才能测。
7. **退出**：让模型调用退出确认工具 → 弹确认框
   - 选「继续访谈」→ 工具结果写明不要重复调用；`write` 仍被拦。
   - 选「退出并落盘」→ 回执给出三步；同一轮内写出规范文件与文档、草稿被删除；此后写入不再被拦。
   - 手动入口：`/spec off` → 回执说模式已关、草稿保留在哪，写入恢复。
8. **跨会话**：保留草稿，开一个新会话随便问一句 → 模型应提到那份草稿，并对照已落盘的规范文件与
   文档判断它是否已被取代：已取代的应被删掉，未被取代的才接着访谈。
9. **软约束**：让模型写一份超过 200 行的规范文件 → 工具结果里带行数警告，写入成功。
10. **文档提醒**：在落盘期间让模型写一份「贴了代码却没写复现步骤」的文档、或首段直接进小节的
    文档、或规范文件里缺文档规则块 → 工具结果里各带一条提醒，写入均成功；再写一份「命令块」
    或「流程图」的文档 → 不提醒。
11. **持久化**：进入模式后关掉会话再恢复 → 模式仍开启（投影从日志恢复）。

## 坑

- **命令记录在处理器之前入日志。** 处理函数里判「本来是否开启」必须用已提交状态，用有效状态会
  读到本次选择本身。实测踩到过，自测脚本有断言锁这条。
- **批准退出后同轮写入靠进程内旁路。** 旁路只保证同一轮的即时判定；持久真相是工具结果的折叠。
  别把旁路当成状态来源。
- **图标跟随当前色等于没有图标。** 图标以数据地址渲染，拿不到宿主样式里的颜色，跟随当前色会
  落到黑色。
- **投影键是全局唯一的。** 与别的插件撞键且状态版本号不同会抛错；相同则共享同一份折叠。改名要
  连带投影键与文档一起改。
- **折叠对无关事件必须返回同一个引用。** 返回新对象会让每次事件都产生下游工作，投影缓存的增量
  机制失效。
- **工具守卫是全局的。** 它按调用所属会话取状态，所以不误伤别的会话；也意味着状态读取必须廉价
  ——目前每次写入都会走一次锚点查找（几次目录探测），可以接受，改成缓存前先量。
- **提示词段落的提供者抛异常会打断整个装配。** 已包异常兜底返回空串。
- **命令的输入提示影响菜单可见性。** 缺输入提示的带参形式会被菜单过滤掉，本命令的提示是
  `[off|初始想法]`。
- **文档提醒的判据是近似值。** 只看围栏块、首段、结构行与图块豁免：命令块与流程图放行，其余代码块
  要在前后几行里找到复现说法才算数。改判据时同时改注入文本里的写法说明。
- **四条文档规则要跟着产出文件走（自举）。** 落盘的规范文件里必须带「过时同步、代码要跟着复现
  步骤、白话导读、讲流程画真的图、决策只记结论」；提醒判据在软约束模块，写法说明在注入文本里。

## 未做的事 / 已知缺口

- 用 shell 写文件不拦（与计划模式同构，刻意取舍）
- 子代理工具集不裁剪（计划模式会裁剪）
- 草稿删除或改名保护在默认工具集下休眠
- 模式互斥单向（计划模式不知道 spec mode 存在）
- 落盘顺序仍是模型驱动，没有代码校验
- 文档提醒只在 spec 工作期间挂出，且只做近似判定
- 草稿不会被自动清理，靠协议要求在确认后删除
- 没有界面状态指示（没有客户端半边）
- 没有配置项，全部是代码常量
- 相对路径草稿按会话工作目录判定，与沙箱工作区根不同基准时是已知边界

## 上游风险

依赖的宿主接口面全部列在 docs/实现逻辑.md 的「宿主接口面」一节。宿主升级后先跑验证清单第 1、4
条——这两条同时覆盖装配与拦截生效。

另有两条与上游实现细节耦合、升级时需要重看的地方：

- **投影注册表契约**：注册时只校验状态版本号是非负整数、同键同版本；状态结构只在恢复持久化
  缓存行时被校验。本插件用的是鸭子类型的校验对象，不是真校验库的 schema——上游若开始要求真
  schema，这里要跟着换。
- **客户端命令菜单**：菜单不给宿主命令行图标这件事写在宿主的命令菜单实现里。若上游开放了图标
  通道，本插件可以直接受益，不需要改代码。
