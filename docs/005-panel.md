# 005 界面

这份文档说明人打开「流程图」页之后看到什么。它建立在 [001 领域模型](001-domain.md) 的概念与 [002 规则与权限](002-rules.md) 的保存规则上。

## 从哪里打开

会话视图顶部的标签栏，「对话」「轨迹」之后多一页「流程图」。页面读的是**这个会话所属项目**的 `.spec/flows/`：会话 id 随每个请求发出，同一仓库的两个会话各看各的自己那份图集。

打开时先列出图集，再自动选中第一张：左栏高亮它，中间画出它，右栏载入它的简报与表单。

## 三个问题

打开这个页面的人依次要回答：

1. 这个项目有哪些图，哪张是总览？
2. 选中的这张画的是什么，从哪一步到哪一步？
3. 它对应哪些需求，我要改哪一处？

## 标签页

页面本身不分标签页：它的三个区域同时可见。

| 区域 | 显示什么 |
| --- | --- |
| 左栏「流程图集」 | 每张图一行：显示名、`kind` 徽标、作用范围、它引用了哪些图。底部一个「新建图」按钮 |
| 中间画布 | 选中那张图的 SVG，按容器宽度缩放；图下方两行提示（怎么选中、怎么连线） |
| 右栏 | 上：需求简报文本域；下：`框` 与 `连线` 两组编辑表单 |

页面宽度不足 720px 时三块改成上下堆叠：图集在上、图在中、简报在下。

## 单张图怎么读

| 元素 | 显示 | 可点 |
| --- | --- | --- |
| 框 | 一段黑字，模块框下面还有它的端口 | 点它选中，右栏出现这个框的表单 |
| 连线 | 一根带箭头的线，分叉时线上有条件标签 | 点它选中，右栏出现这条线的表单 |
| 框右侧的圆点 | 一个小圆 | 从它拖到另一个框，连出一条新线 |
| 框里的动作 | 按层次自上而下排；一层放不下就折到下一行继续 | 拖动只改同一行内的先后 |

选中的框或线会高亮，右栏同时出现它的字段。没选中任何框或线时，右栏只显示简报与「加一个框」「加一条连线」「加一个模块框」三样。

## 工具条与表单

| 控件 | 作用 |
| --- | --- |
| 保存 (Ctrl/Cmd+S) | 先校验再写盘；失败时把错误逐条列出来 |
| 删除 | 删掉当前图；被引用时显示宿主返回的拒绝原因 |
| 新建图 | 弹表单：编号、显示名、作用范围、类型 |
| 状态字 | `未保存` / `保存中…` / `已保存`；冲突时显示「盘上的图已经变了」并给出一个「重新载入」按钮 |
| 框的表单 | `框里的话`；模块框改成端口的多行文本域；每个框有上移、下移、删除 |
| 连线的表单 | `条件`；每条线有删除 |
| 加一个框 / 加一条连线 / 加一个模块框 | 一次加一个元素；加连线时先选两头 |

新建或保存后图会重画，重画与模型写盘是同一次请求。

## 设计原则

1. **页面不判断图合不合格。** 校验与它返回的错误都在宿主，页面原样显示；判两次就会出现两套规则。
2. **位置不是可编辑的。** 框落在哪一行由层决定，同一行里排第几由声明顺序决定。要改层次就改连线，要换左右就调顺序。
3. **一次只显示一张图。** 左栏是索引，中间是那张图，右栏是这张图的需求；找另一张图是点左栏。
4. **保存是显式动作。** 没有自动保存，也没有合并；冲突时先看盘上是什么再决定。
5. **窄窗口改形状，不改内容。** 720px 以下换堆叠布局，控件换行，字段一个不少。
6. **模块框的字来自子图。** 页面上改不了模块框的文字，改的是那张子图的显示名。
