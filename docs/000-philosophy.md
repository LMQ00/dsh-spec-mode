# 000 原则

这份文档给出这个项目做取舍的判据：一个功能做不做、一个字段存不存、一句话写不写。后续每份文档的每个决定都能回到这里的一条。

## 访谈期间只写一个文件

spec mode 开着时，唯一可写的文件是 `.spec/draft.md`。

**判据：** 这个写入能不能由插件自己的工具在退出之后完成？能，就交给工具做。

模型在访谈里写草稿；图集、简报、`AGENTS.md` 由 `spec_resolve` 在用户点「退出并落盘」之后写。守卫因此只认一个路径。

## 图和它的文件是同一份

一张图就是 `.spec/flows/<id>.md` 这一份文件：标题、范围行、`mermaid` 块、简报都在里面，`.md` 同时是存储格式和阅读格式。

**判据：** 这份内容能不能只存一遍？能，就别再存一份派生的。

框和线的位置由 mermaid 在浏览器里按源码算出来，文件里存的是那段源码；编辑器预览、仓库页面、流程图页渲染的是同一段文字。模块框上的字也在渲染时从被引用的那张图的标题取，名字只存在一个文件里。

## 产物只写需求

简报四节：目标、要做什么、验收、约束。图里的框只写「谁做什么」。

**判据：** 这句话换成另一种实现之后还成立吗？成立，它属于理由、背景或方案比较，归提交历史与对话；不成立，它是产品特性，进产物。

代码、动机、被否决的方案、备选方案比较都留在对话里；框里写的是发生什么。读产物的人要的是「做什么」。

## 一条规则只有一个实现

图合不合格由 `mermaid-graph.js`、`chart-md.js` 与 `flows.js` 判定，界面只显示它们返回的错误。

**判据：** 这条规则换个入口还生效吗？会，它就是规则，写进校验器；只在某个入口生效，它属于那个入口。

`spec_resolve`、`flow_write`、`/spec/flows/save`、`/spec/flows/create`、`/spec/flows/delete` 五个入口跑同一套校验，所以工具接受的就是落盘会接受的，界面能存的就是模型能交的。

## 一张图只画一段流程

一张图恰好一个起点，可以有多个终点，可以有回箭头。

**判据：** 这张图能不能被一句话概括成「从哪一步到哪一步」？能，它就是一张图；概括不了，就拆成几张。

文件里的范围行逼着作者把这句话写下来，写「本次」「相关」这类无边界说法会被拒。不同功能的模块接到同一个起点上。

## 写下的名字都是当前有效的

文档与产物里的每个名字——路径、命令、字段、配置项——都指向现在存在的东西。

**判据：** 读者照着这个名字做，会走到一个真实存在的地方吗？会，就留下；会落空，就先把它做出来，或者换一个真实的名字。

这条管的是措辞：说的是现在有什么、怎么用、下一步做什么。
