# 003 生命周期

这份文档跟着一次访谈走完：从用户输入 `/spec` 到图集写进磁盘、草稿消失。它建立在 [001 领域模型](001-domain.md) 的概念与 [002 规则与权限](002-rules.md) 的约束上。

## 阶段表

从上往下读，第一条成立的为准。

| 阶段 | 成立条件 | 界面文字 |
| --- | --- | --- |
| 未启用 | 会话日志里没有生效的 `/spec` | 命令菜单里的 spec 可点 |
| 访谈中 | 模式生效，草稿在盘上 | 模型按协议提问；写入被拦，回执说明只读 |
| 待确认 | `spec_resolve` 已通过校验，确认框开着 | 「退出 spec mode 并落盘？」 |
| 已落盘 | 图集写完，模式退出 | 工具结果列出每张图的 `.md` 路径与简报是否已写 |
| 看图改图 | 模式关闭，`.spec/flows/` 里有图 | 流程图页左栏列出图集 |

## 执行者

| 项 | 内容 |
| --- | --- |
| 身份 | 会话本身，状态按会话分键，投影键是 `spec` |
| 名字 | 命令 `spec`，退出工具 `spec_resolve`，编辑工具 `flow_read` / `flow_write` |
| 目录 | 项目锚点下的 `.spec/`；锚点是工作目录向上最近的带 `.git` 的目录，找不到就是工作目录本身 |
| 权限 | 访谈中模型只能写 `.spec/draft.md`；落盘由插件执行，模型只交参数 |
| 接入方式 | 宿主服务 `commands`、`tools`、`systemPrompt`、`sessionProjections` 是必需注入；`userQuestions`、`planMode`、`webServer`、`connection` 按存在与否读取 |

模式不在领域模型里：它属于会话日志的折叠结果，不写进产物。

## 一次访谈怎么走

1. 用户输入 `/spec` 或 `/spec <想法>`。`command/run` 先记下待定的选择，处理器再执行。
2. 处理器确认计划模式不活跃，创建 `.spec/`，把想法作为这一轮用户消息提交（裸 `/spec` 不提交）。
3. `command/done` 落定模式状态。此后每一轮请求都带上 `spec:policy` 提示词段落。
4. 模型每轮把结论写进草稿，末尾输出一行 `已定 ｜ 待定 ｜ 假设`。
5. 用户确认访谈结束后，模型做一次整体回述，再调 `spec_resolve`。
6. 工具校验；不通过就报行号、字段路径与图 id，模型改完再调，直到通过。
7. 通过后弹确认框，正文列出每张图的显示名、作用范围与图上那些框；模块框写它指向的图。
8. 用户点「退出并落盘」→ 每张图写成 `.spec/flows/<id>.md`、删掉删除列表里的图、删掉草稿、退出模式。
9. 模型接着更新 `AGENTS.md`。

## 并发与配额

| 项 | 规则 |
| --- | --- |
| 同时进行的访谈 | 一个会话只有一个模式状态，`running` 只记最后一条 `/spec` 命令 |
| 模式互斥 | 计划模式活跃时进不来；spec mode 不写计划模式的状态 |
| 子代理 | 状态按会话分键，子代理日志里没有进入记录，所以不受约束 |
| 并发落盘 | 无配额。两次落盘靠修订号发现对方的写入 |
| 页面保存 | 一次写一张图；冲突时返回 409 而不是重试 |

## 结束条件

模式在三种情况下结束：

| 出口 | 谁触发 | 落盘 | 草稿 |
| --- | --- | --- | --- |
| `spec_resolve` 被批准 | 用户在确认框里点「退出并落盘」 | 写本次提交的图，删掉删除列表里的图 | 删除 |
| `/spec off` | 用户直接运行命令 | 不写，注入一行落盘指引让模型自己写 | 保留 |
| 会话结束 | 宿主 | 不写 | 保留，下次有新会话时提醒 |

看图改图不属于任何一种访谈：模式已经关闭，流程图页、`flow_write` 与编辑器的直接改动都落在盘上的 `.md` 文件里。

## 失败与恢复

### 校验不通过

工具抛错，正文是「`spec_resolve` 的参数不合格——先改这些再调一次：」加逐条问题。确认框不弹，模式不变，草稿不动。

### 确认框被关闭

`userQuestions.ask` 抛 `ASK_CANCELLED` 时转为一条错误：模式保持开启，停下等用户的消息，不重试。

### 用户选「继续访谈」

工具抛错，写明模式保持、工作树仍只读。图集文件一个都没写。

### 写盘失败

报错带目标路径：模式不退出，草稿保留，修正后重新调用。已经写成功的文件留在盘上。

### 没有确认框通道

`userQuestions` 缺席时工具抛错，提示用户运行 `/spec off` 退出。

### 会话恢复与分叉

状态从会话日志折叠得出：`command/run` + `command/done` 决定模式，`tool/call` + `tool/result` 决定退出。恢复、分叉、重放都能还原同一个状态，不需要插件自己的事件类型。

### 重启

同一个进程里批准过退出的会话记在一个 `WeakSet` 里，让工具调用之后紧跟的写入不被尚未折叠的投影拦住。进程重启后这个集合为空，此时靠 `tool/result` 的折叠结果。
